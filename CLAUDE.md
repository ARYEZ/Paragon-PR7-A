# Paragon PR7-I: notes for Claude

This repository starts as a copy of **Paragon PR7-D** (the drum instrument, repo `ARYEZ/Paragon-PR7-D`) at PR7-D **0.60.0** plus its CI fix for pluginval (branch `claude/new-session-yhgoe4`, commit `aab0ee8`), full history included, to become **Paragon PR7-I**, the **guitar instrument** of the PR7 family: a VST3 instrument played from MIDI, a spiritual cousin of Impact Soundworks' Shreddage 3 (it works the way that plugin works, but sounds and runs the way the owner wants; no Kontakt). The owner plays **djent and progressive metal**: weigh features by what helps tight, palm-muted rhythm parts. Siblings: **PR7-G** (the guitar amp-and-effects plugin, `ARYEZ/Paragon-PR7-G`), **PR7-D** (drums), **PR7-K** (synth), **PR7-B** (bass), **PR7-V** (vocal), **PR7-C**, **PR7-X** (utility; PR7-E until its 0.20.0), **PR7-M**, and **PR7-S** (the owner's DAW, based on Cubase 15).

**PR7-G is the amp side** (checked in its README, November 2026: Neural Amp Modeler captures, cab IRs, pedals). So PR7-I puts out a clean DI guitar and the owner puts PR7-G after it; PR7-I doesn't rebuild amps.

**From Shreddage 3.5 Jupiter's manual (our summary, for "works the way it works"):**
- **Engine:** every string recorded from open up the neck, so a pitch sounds different on each string. A note's string and fret come from: the strings already held, legato or not, a virtual **hand position** (low on the neck stays low), **force string**, and the **fretting mode** (Natural: follows the hand; Sweep: prefers neighbouring strings; Moving Lead: the hand climbs as the notes rise; Polyphonic: as many strings as possible, for chords). **Performance styles** are presets of those (Standard: low on the neck, open strings; Mono / Poly Lead; Rhythm; No Legato; Workstation / Keyboard Mode: every note fixed to a string and fret, unlimited notes per string). **Mono**. **Capo** (drag on the fretboard).
- **Picking mode:** Up, Down, Alternate, Economy (same stroke when crossing strings); down and up strokes are separate round-robins with their own start offsets.
- **Poly input latency:** a look-ahead window (default about 0 ms, a 0.05 ms minimum so a keyswitch on the same grid line comes first) gathers chord notes before voicing them; too long breaks fast passages (16ths at 120 BPM are 125 ms apart).
- **Articulations** (their default keyswitches, latching, low C-1 up): Sustain (vel 1-119), Rake (120-126, a muted strum before the note), Pinch harmonic (127), Mute (palm mute: **velocity sets how muted**, very muted to half), Staccato, Power-chord sustain / mute / staccato, Tremolo (looped), Choke, Harmonics, Tapping, FX. Legato: hammer-on / pull-off within a range (default 2 semitones, same string), slides (up to 12 semitones). Releases: pitched, power-chord, unpitched noises on note-off.
- **Articulation mapping:** each articulation has up to 3 rules (keyswitch latching or held, velocity range, CC range, pitch wheel range, key range, sustain pedal); a conflict is shown when two share a trigger. Per articulation: volume, start offset, velocity to volume, which velocity picks which dynamic layer (a drawn step table), ADSR; Mute adds TIGHTNESS (how fast it decays) and velocity to tightness.
- **Strumming:** keyswitches strum what's held (down, up, partial down / up by strum distance, muted, choked); per-string pick keys (one key per string); strum mode (held notes only set the chord); strum on poly input; speed / volume / distance from velocity or a CC.
- **Other keyswitches:** force string (one key per string and one to turn it off), set hand position (by the keyswitch's velocity), legato on / off, slide, fret noise, slide in / out, thrash (repeat the last note); picking-mode and fretting-mode keys.
- **Advanced:** transpose +/-12, MIDI guitar mode (a channel per string), velocity curve (min, max, curvature), shred window / offset (fast notes start later in the sample and darker), anti-repetition (neighbouring samples now and then), ringing (an open string touched now and then), DI line noise, hand reset time, release on hand move / chord change.
- **Tone:** volume, tone (a gentle low-pass), bite (an EQ: brighter, less low-mid), extra attack (pick noise by velocity), pitch-bend range, unison bend, vibrato (LFO or recorded), multi-tracking (up to 4 guitars, each its own samples, panned).
- **Their tip for tight metal:** move the guitar track 20-30 ms earlier in the DAW (plus any look-ahead).

## The guitar's code (0.2.0, `source/guitar/`)

- `Tuning.h`: 7 strings, string 0 = the low A (a player's string 7) to 6 = the high E, `openNotes` 33 40 45 50 55 59 64, frets 0-24, `Articulation` (sustain, mute: append only), `Stroke`.
- `Fretting.*`: `choose` (cost: frets outside the hand's span, open strings free while the hand is at fret 5 or lower, a busy string +100, ties to the lower string; FORCE STRING wins where it can), `chooseChord` (lowest note first; an AUTO hand moves after each note, so D5 is a barre), `followHand`, `FretMode` natural (span 4) / polyphonic (5). Nothing allocated.
- `RenderList.*` (`guitar::renders`): `takes` per string (fret, layer, round-robin, stroke; `slotSeconds` 5.5 apart, notes `holdSeconds` 4 long, 2 s lead-in, keyswitches 0.25 s before each note), `toMidi` (force string `keys::forceStringLowA + string`, legato off D#0 = 27, articulation C-1 = 12 / C#-1 = 13, picking C7 = 108 up / C#7 = 109 down, velocities 45 / 85 / 118: sustain stays below the reference's rake (120-126) and pinch (127)), `fileName`, `takeFileName` ("Sustain/s0_f05_l2_d_r1.wav") / `parseTakeFile`.
- `RenderImport.*`: `importAudio` / `importFile`: the render's offset (median onset of the first dozen takes against the list, onset = first sample at a tenth of the peak), each take cut from 30 ms before its onset for the note plus 80 ms, faded, mono, 24-bit at the render's rate; `pitchOf` (Yin's difference function within half an octave of the expected pitch) checks every take: over 30% beyond 40 cents (or too short, or silent) refuses the file and writes nothing.
- `GuitarLibrary.*`: `Library::load` (a folder's `Sustain/` and `Mute/` takes; each keeps `headSeconds` 0.25 in memory, the rest a `StreamSource` for `streaming::Streamer`), `find` (exact; the other round-robin; the other stroke; the nearest dynamic; the nearest fret on the string, pitch-shifted; the same note on another string), `count`, `takesPerString` (300).

## Rules (from the owner and the family's CLAUDE.md files)

- **Names:** our own designs, "inspired by"; **no Impact Soundworks, Shreddage or Kontakt names or branding** on the plugin (nor PR7-D's Toontrack / Superior Drummer / EZdrummer ones). Never read or ship their library files: Kontakt libraries are protected, and we never get round copy protection.

- **Manuals** (Shreddage 3's, and PR7-D's SD3 extract) stay with the owner (uploads / `ARYEZ/manuals`): never commit them.
- **Colours: the PR7 family's only** (the owner, 0.11.0): the red / pink / orange range (hue about 318° through 0° to 42°), pearl white and onyx (greys, near black). No green, blue, purple, yellow or cyan anywhere, JUCE's defaults included (`ParagonLookAndFeel` sets a family `ColourScheme` first: its fill and highlight orange). `PluginTests.cpp` checks the fretboard's string colours are in range; **0.3.0 should add a test of the look-and-feel's palette** (PR7-D's went with its song tests); check new screens' pixels too.
- Ask for source material (manual chapters, example files) rather than invent specifics; say when something is a guess or our own design; say what can't be checked here (listening).

## The project

- An AGPLv3 **JUCE VST3** instrument in the PR7 family's look, sharing the family's code.
- **Code layout:** the guitar in `source/guitar/`, disk streaming in `source/dsp/`, UI in `source/ui/`, parameters in `source/Parameters.*`, presets ("rigs" in the code, as across the family) in `source/rigs/`, tests in `tests/`.
- **Parameters:**
  - Saved by ID and choices by **index**: only ever *append* choices, never reorder (`ParamIDs::fretModeNames`, `pickModeNames`, `forceStringNames`, `guitar::Articulation`).
  - New parameters get a new version hint number (0.2.0's are 1; the next release's new ones 2...).
  - Migrations for changed defaults live in `setStateInformation` and `Rig::fromXml`.

## Build, test, check

- **Build:** `cmake -B build && cmake --build build -j8`. On a fresh Linux machine, install the packages listed in `.github/workflows/build.yml` first. `-DPARAGON_LTO=OFF` links far faster while working (CI and releases keep link-time optimisation on).
- **The guitar's code alone:** `cmake --build build --target GuitarCoreTests && build/tests/GuitarCoreTests` (no plugin, no LTO: quick). Its hidden `"[render-lists]"` test writes the seven render lists (`PARAGON_RENDER_LISTS=<folder>`).
- **Tests (Catch2):** `xvfb-run -a build/tests/ParagonX1Tests`. All must pass. Windows gives a thread 1 MB of stack (Linux 8 MB): keep big data (patterns, tables) on the heap, never inline in `ModMatrix`, `Rig` or the kit's settings (`tests/StackSizeTests.cpp`); before a release run the tests once under `ulimit -s 1024` to catch what Linux hides. New features get tests that check what the feature really does to the sound (levels, timing to the sample, frequencies), not just that it runs.
  - **A/B against the reference** (after 0.4.2): `PARAGON_AB_A=ref.wav PARAGON_AB_B=pr7i.wav PARAGON_AB_MIDI=riff.mid build/tests/GuitarCoreTests "[ab-compare]"` prints, note by note, how late each pick lands after its note-on, its level, how far it has fallen 30-50 ms after its note-off, and whether consecutive hits of a note are the very same take (correlation 0.99+): the owner's "repeated notes" and "note endings" as numbers. Checked on made-up files (12 ms planted, 12 ms read; 0 / 15 vs 15 / 15 repeats).
  - Made-up guitars: `GuitarTests.cpp`'s `toneGuitar` (every string, fret, dynamic, stroke and round-robin a tone at its pitch, level by dynamic and stroke) and `fakeRender` (a render of a list: tones at the list's times, a little late); `tests/TestUtils.h`: `levelAt`, `rms`, `frequencyOf` (zero crossings; `guitar::frequencyOf` is a note's Hz)...
  - Plugin tests run **non-realtime** (`setNonRealtime (true)`): streamed takes wait for the disk; live, the blocks run far faster than real time and the disk thread would fall behind.
  - Hits in tests go in as MIDI (at a sample position), **not** through `getKeyboardState().noteOn`: JUCE spreads the keyboard's presses across the block by the clock, so two presses can land at different samples on different runs (it made "identical" runs differ in 0.1.0).
- **pluginval:** `xvfb-run -a <pluginval> --strictness-level 10 --validate-in-process --validate "build/ParagonX1_artefacts/Release/VST3/Paragon PR7-I.vst3"`. Check its exit code. CI runs it too. Linux pluginval sometimes crashes in its own host at shutdown, after SUCCESS (about 1 run in 6-16 here: a segfault in `juce::RunLoop::Impl::registerEventHandler` on its message thread). Since 0.60.0 CI gives that crash after SUCCESS up to 3 more tries (it failed both of the old two); a crash before SUCCESS or any other failure fails the build. If CI still fails on it, reproduce under gdb before calling it that.
- **Screenshots** for checking the UI, via `xvfb-run -a build/tests/ParagonX1Tests "[snapshot]"` with environment variables (see `tests/EditorSnapshot.cpp`): `PARAGON_SNAPSHOT` (output path), `PARAGON_SNAPSHOT_RACK=fretting|noises` (the rack's other pages), `PARAGON_SNAPSHOT_RENDERS=noises` (RENDERS' NOISES tab), `PARAGON_SNAPSHOT_WIDTH` (default 1600; 3200 for 2x), `PARAGON_SNAPSHOT_PAGE=guitar|presets|settings`, `PARAGON_SNAPSHOT_NOTES=1` (a made-up guitar, three strings complete, D5 held: lit on the fretboard; `=2` an open power chord and a note up the neck), `PARAGON_SNAPSHOT_PROGRESS=1` (an import 62% done), `PARAGON_SNAPSHOT_MIDI=1` (MIDI links, a knob learning), `PARAGON_SNAPSHOT_PRESET`, `PARAGON_SNAPSHOT_PARAMS=id=value,...`, `PARAGON_SNAPSHOT_FINISH=0|1|2`. Render, look, crop and zoom before claiming a visual change is right.

## Releases

- Bump `project(ParagonX1 VERSION x.y.z)` in CMakeLists.txt and add a matching `## x.y.z` section at the top of CHANGELOG.md, then push.
- CI builds Windows and Linux (macOS left out since 0.46.0, the owner's choice: GitHub stopped giving its job a machine; the matrix entry is kept commented out in `build.yml`) and publishes a GitHub Release with the two zips, using that changelog section as the notes. It publishes from a push to **any** branch whose version isn't released yet.
- After pushing, check the release published (both zips) about 15-20 minutes later, **and that its `target_commitish` is your commit**. If the version was already taken, CI skips silently and the release you'd link is someone else's build. Send the owner the link.
- **One chat per plugin at a time.** In October 2026 two chats released PR7-G and PR7-V under the same version numbers: one chat's releases were skipped, and features (and a UI fix) went missing from the builds the owner installed. Before choosing a version, check the repo's tags *and* other branches for unreleased work; if another branch is ahead, merge it first so every release contains everything.
- The owner installs from GitHub Releases on **Windows**.
